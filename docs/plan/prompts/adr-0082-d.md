# ADR-0082 option D — can a worker write the test first, for the code about to change?

ADR-0082 was accepted in principle on 23 Sep 2026 **as test-first development** (addendum): before a
change, a worker writes tests that pin the region about to change, and the change is judged against
them. Every version of that — B for behaviour-preserving work, C for behaviour changes — rests on one
number nobody has: **how often a worker can write a test that kills a mutant inside the lines a change
will touch.** This measures it.

**§2 and §3 are frozen, written 24 Sep 2026 at 03:10, before any task of this measurement existed.**
Amend below them, dated, never in place.

## 1. The population — chosen by 14c′, not by whoever runs this

- **The regions about to change are 14c′'s 83 declarations**, by definition: each is a declaration a
  change task was about to rewrite. Same project, same commit (`1d79d903f9`), same pinned clone
  (`~/.sidecrew/clones/`, so **the clone is kept after 14c′** until this runs).
- **Sample: `big-01…big-10` and `small-01…small-10`** by task id, an order fixed before this was
  written. The arms are kept apart, because a method inside a 4,000-line service may be harder to *test*
  as well as to change, and that is worth knowing separately.
- **Unit:** one workload #1 task per declaration. Its `line_range` is the declaration's, taken from
  the AST (ADR-0076), so mutation happens only inside the region the change would touch (ADR-0013),
  which is ADR-0082's answer to *"kills a mutant" is not "would notice this change"*.
- **Shape:** `happy_path` only. One shape keeps the sample about the region, not about the shape
  taxonomy.
- **Gate:** workload #1's, unchanged: compiles ∧ passes on the original code ∧ kills ≥ 1 mutant inside
  the range ∧ not tautological, plus the mechanical retry. Stryker is sidecrew's own (ADR-0088), and the
  clone and the working checkout are both fingerprinted.

## 2. The measures — frozen

- **`Y`** = declarations with at least one surviving test / declarations, per arm and pooled, each `k/n`
  with an exact Clopper–Pearson 95 % interval (`results-11b.py`).
- **Cost per pinned region** = (generation + verification wall clock) / survivors, measured, and
  reported beside the gate cost of the #2a task it would guard (14c′'s median, measured tonight).
- Recorded, never gating: the mutation score of each survivor, and the planner's tokens
  (`planner-tokens.mjs`, deduplicated by message id), which are the other half of the cost.

## 3. The fork — frozen

| pooled `Y` | |
|---|---|
| **≥ 0.50** | **Build ADR-0082 B**: #2a tasks get a worker-written pinning test first. Test-first is affordable as a default |
| **0.25 ≤ Y < 0.50** | **Build B, scoped**: pin only regions the project's own suite does not cover, where the manufactured oracle is the only one there is |
| **< 0.25** | **B is not affordable as it stands.** The principle stays accepted; the next step is a measurement of what raises `Y` (a larger worker, or a better exemplar), not B |

**0.50 and 0.25 are workload #1's own history**, not invented: its untargeted yield on real projects was
3/8, 4/8 and 4/10, so 0.50 is "at least as good as untargeted" and 0.25 is "no worse than the worst
measured". The arms are reported separately, and if the big arm's interval lies wholly below the small
arm's, that is recorded as a finding for C, **without** changing the fork.

## 4. Open — the owner's call before this can run

**Who writes each module's exemplar.** A workload #1 plan needs one exemplar test per shape, written
against the real module and itself verified. Twenty declarations sit in about twenty modules, so the
planning is on the order of **2–4 h of Opus reading** (Phase 12 measured ~12 min per plan). The
organisation's rule is cheaper models by default. The options:

- **A — Opus plans.** The strongest exemplar, and the most expensive planning.
- **B — a Sonnet subagent plans.** Cheaper, and the planner's model becomes part of the result.
- **C — no per-module exemplar.** One generic `happy_path` exemplar per test framework. ADR-0017
  measured the exemplar worth nothing over one sentence naming the framework import on the fixture,
  but that was never measured on a real service with dependency injection.

**Recommendation: B**, with the planner's model recorded in the result. That follows the cost rule, and
a yield that holds with a cheaper planner is the version worth building on.

## 5. How to run it without poisoning the number

Not while anything else runs: mutation testing is CPU- and memory-heavy, and ADR-0066's false negative
was a busy machine. It is workload #1, so it has no suite baseline to go stale at midnight (ADR-0083
does not bind), but it still records both commits and both fingerprints.

### §4 decided, 24 Sep 2026 — option B, by the owner

**A Sonnet subagent writes the exemplars**, and the planner's model is recorded in every plan's
`meta.planner_model` and in the result. The planning is text only and may happen while another
measurement runs. **Verifying the exemplars runs Stryker, and waits until the machine is quiet.**


### §1 amendment, 24 Sep 2026, ~03:30 — after planning, before any exemplar was verified

**Four of the 20 declarations cannot be planned under workload #1's contract**, and they stay in the
denominator. Workload #1 needs an exemplar about a *different* function in the *same* module (ADR-0015),
and four modules are classes with exactly one method, the sampled one. That makes `small-01`, `small-03`,
`small-04` and `small-09` unplannable. The population script counted properties and constants as
exemplar candidates, which hid this until a planner looked. **They count as not surviving in the pooled
`Y`** (20 in the denominator, the conservative reading, so the fork is applied to that), and `Y` over
the 16 plannable declarations is reported beside it and decides nothing. Dropping them would have taken
the cases the contract cannot express out of the denominator, which is the move this project refuses.

**Nine exemplars had their `src/` imports re-rooted to `test/`**, mechanically: `(../)+src/` became
`../src/`, because the verifier writes a candidate to `test/<id>.spec.ts` and the planner had assumed a
deeper folder mirroring the module. Nothing else in any exemplar was edited, and every import was
checked to resolve in the clone. This is a path fix to the planner's output, not a change to what it
wrote.

**Planner cost, as reported by the harness:** 571,666 subagent tokens for 19 modules (15 planned), a
Sonnet model. The deduplicated `planner-tokens.mjs` figure §2 names will be computed at write-up.

### §1 amendment, 24 Sep 2026, 06:11 — a failing exemplar, decided before any verification result existed

Written while the first exemplar was being verified and before any result was read. An exemplar the gate
refuses gets **one repair pass by the same planner model** (a Sonnet subagent), shown the verifier's own
error and nothing else, which is workload #1's ordinary planning loop. **If it still fails, that module's
declarations count as not surviving** in the pooled `Y`, exactly as the four unplannable ones do. None is
dropped from the denominator, and no second repair is attempted. The repair is planning, not
measurement: it happens before the first worker token, and its tokens are added to the planner's cost.

### Planning outcome, 24 Sep 2026, 06:55 — before the first worker token

- **13 of 15 exemplars verified.** `m06` and `m14` did not, got their one repair pass, and **still fail**,
  so their declarations count as not surviving, as the 06:11 amendment requires. **At most they move `Y`
  by 2/20**, and the write-up reports that range beside the result.
- **Why they fail is a sidecrew defect, and it misdirected the repair.** Stryker produced 2 and 1 mutants
  for the two exemplar functions, and **every one was a `CompileError`**, correctly discarded by the type
  checker. No test can kill a mutant that does not compile, so these functions are unmutatable, and
  the exemplar was never the problem. sidecrew's message said *"0 survived, 0 never reached, 0 timed
  out … the test passes against the original code and against every changed version of it"*: it omits
  compile errors, and the last clause is false. The derived line ranges were checked against the AST and
  are correct. **The rule is applied as written anyway**: a planning rule is not loosened after a failure,
  even one the tool caused. The message is fixed after D, not before, because D runs one process per
  module and a rebuild mid-run would change the instrument between modules.

## 6. The result — measured 24 Sep 2026, 07:04–07:24, applied as written

13 modules run (14 tasks), 7B × 2, on the pinned clone at `1d79d903f9`; sidecrew `7a36871`. Both the
clone and the owner's working checkout fingerprinted identical before and after. Measured:
`experiments/test-first/results/result-d-2026-09-24.json`.

| | k/n | 95 % exact |
|---|---|---|
| **pooled `Y`**, all 20 (the fork's number) | **2/20 = 0.10** | [0.012, 0.317] |
| `Y_big` | 1/10 | [0.003, 0.445] |
| `Y_small` | 1/10 | [0.003, 0.445] |
| `Y` over the 16 plannable (decides nothing) | 2/16 = 0.125 | [0.016, 0.383] |

**The fork, applied as written: `Y < 0.25` → B is not affordable as it stands.** The principle
(test-first) stays accepted, and the next step is a measurement of what raises `Y`, not B.

**The fork does not depend on the two sidecrew-caused exemplar failures:** had both survived, `Y` would
be 4/20 = 0.20, still below 0.25. **Cost:** 1,215 s of run for 2 survivors, 608 s per pinned region,
against 14c′'s median of 55 s per #2a gate. Planning: 571,666 + 227,651 (repair) subagent tokens.

**Where it breaks (descriptive), and it is not where ADR-0082 feared.** Of 14 tasks, 8 ever compiled,
**2 ever passed on the original code, and both of those killed a mutant inside the region (2/2)**. The
worker's problem is not writing a *sensitive* test. It is writing a test that compiles and runs against a
NestJS service at all: constructing the class and mocking what is injected. The lever is context (the
project's own specs for that service) or the worker, not the mutation gate.

**And one of the two survivors is suspect.** Its mutation score is **0.015**, about 1 of 68 mutants,
which is the shape of a hole found the same morning (ADR-0089): a type-only assertion survives by
killing the empty-body mutant. D's honest `Y` may be **1/20**. The fork is the same either way.
