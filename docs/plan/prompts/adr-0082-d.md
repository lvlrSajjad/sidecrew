# ADR-0082 option D — can a worker write the test first, for the code about to change?

ADR-0082 was accepted in principle on 23 Sep 2026 **as test-first development** (addendum): before a
change, a worker writes tests that pin the region about to change, and the change is judged against
them. Every version of that — B for behaviour-preserving work, C for behaviour changes — rests on one
number nobody has: **how often a worker can write a test that kills a mutant inside the lines a change
will touch.** This measures it.

**§2 and §3 are frozen, written 24 Sep 2026 at 03:10, before any task of this measurement existed.**
Amend below them, dated, never in place.

## 1. The population — chosen by 14c′, not by whoever runs this

- **The regions about to change are 14c′'s 83 declarations**, by definition: each is a declaration a
  change task was about to rewrite. Same project, same commit (`1d79d903f9`), same pinned clone
  (`~/.sidecrew/clones/`, so **the clone is kept after 14c′** until this runs).
- **Sample: `big-01…big-10` and `small-01…small-10`** by task id, an order fixed before this was
  written. The arms are kept apart, because a method inside a 4,000-line service may be harder to *test*
  as well as to change, and that is worth knowing separately.
- **Unit:** one workload #1 task per declaration. Its `line_range` is the declaration's, taken from
  the AST (ADR-0076), so mutation happens only inside the region the change would touch (ADR-0013),
  which is ADR-0082's answer to *"kills a mutant" is not "would notice this change"*.
- **Shape:** `happy_path` only. One shape keeps the sample about the region, not about the shape
  taxonomy.
- **Gate:** workload #1's, unchanged: compiles ∧ passes on the original code ∧ kills ≥ 1 mutant inside
  the range ∧ not tautological, plus the mechanical retry. Stryker is sidecrew's own (ADR-0088), and the
  clone and the working checkout are both fingerprinted.

## 2. The measures — frozen

- **`Y`** = declarations with at least one surviving test / declarations, per arm and pooled, each `k/n`
  with an exact Clopper–Pearson 95 % interval (`results-11b.py`).
- **Cost per pinned region** = (generation + verification wall clock) / survivors, measured, and
  reported beside the gate cost of the #2a task it would guard (14c′'s median, measured tonight).
- Recorded, never gating: the mutation score of each survivor, and the planner's tokens
  (`planner-tokens.mjs`, deduplicated by message id), which are the other half of the cost.

## 3. The fork — frozen

| pooled `Y` | |
|---|---|
| **≥ 0.50** | **Build ADR-0082 B**: #2a tasks get a worker-written pinning test first. Test-first is affordable as a default |
| **0.25 ≤ Y < 0.50** | **Build B, scoped**: pin only regions the project's own suite does not cover, where the manufactured oracle is the only one there is |
| **< 0.25** | **B is not affordable as it stands.** The principle stays accepted; the next step is a measurement of what raises `Y` (a larger worker, or a better exemplar), not B |

**0.50 and 0.25 are workload #1's own history**, not invented: its untargeted yield on real projects was
3/8, 4/8 and 4/10, so 0.50 is "at least as good as untargeted" and 0.25 is "no worse than the worst
measured". The arms are reported separately, and if the big arm's interval lies wholly below the small
arm's, that is recorded as a finding for C, **without** changing the fork.

## 4. Open — the owner's call before this can run

**Who writes each module's exemplar.** A workload #1 plan needs one exemplar test per shape, written
against the real module and itself verified. Twenty declarations sit in about twenty modules, so the
planning is on the order of **2–4 h of Opus reading** (Phase 12 measured ~12 min per plan). The
organisation's rule is cheaper models by default. The options:

- **A — Opus plans.** The strongest exemplar, and the most expensive planning.
- **B — a Sonnet subagent plans.** Cheaper, and the planner's model becomes part of the result.
- **C — no per-module exemplar.** One generic `happy_path` exemplar per test framework. ADR-0017
  measured the exemplar worth nothing over one sentence naming the framework import on the fixture,
  but that was never measured on a real service with dependency injection.

**Recommendation: B**, with the planner's model recorded in the result. That follows the cost rule, and
a yield that holds with a cheaper planner is the version worth building on.

## 5. How to run it without poisoning the number

Not while anything else runs: mutation testing is CPU- and memory-heavy, and ADR-0066's false negative
was a busy machine. It is workload #1, so it has no suite baseline to go stale at midnight (ADR-0083
does not bind), but it still records both commits and both fingerprints.
